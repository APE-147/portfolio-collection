# yolo

## 一句话

一个统一启动 Claude Code、Codex、Gemini 等开发 CLI 的跨平台入口。

## 解决的问题

多个 AI CLI 并行使用时，真正消耗体验的通常不是模型能力，而是每个工具的启动方式、认证流程、环境要求和更新路径都不一样。单看每个差异都不大，叠在一起以后，日常切换会变得很碎。

这种问题最烦的地方在于，它很少让系统彻底不能用，却会一直增加摩擦。久而久之，人花在“把工具叫起来”上的注意力，可能比真正使用工具还多。

## 为什么选这个方案方向

最简单的做法是给每个 CLI 各写一层 alias 或包装脚本。短期确实省事，但随着工具增加、平台变化、认证方式变化，这些局部补丁会越来越不一致。

所以我没有继续沿着“每个工具修一点”的方向走，而是把入口统一起来。重点不是让所有工具看起来一样，而是先把最容易分裂的启动和认证体验收敛到一个稳定边界里，让用户不必反复记住每个工具的特殊规则。

## 我关注的效果 / 质量标准

我最在意的是跨平台行为尽量一致，认证链路尽量平滑，日常启动摩擦足够低。

一个真正好的入口工具，不该要求用户脑子里同时维护几套不同心智。它应该让常用动作稳定下来，让切换本身变轻。

## 我想展示的工程判断

这个项目体现的是我一贯的一个判断：很多表面上的工具问题，其实是入口不统一、状态不一致、心智成本过高的问题。

先把入口做稳，后面的工具生态才有可能真正顺手。
