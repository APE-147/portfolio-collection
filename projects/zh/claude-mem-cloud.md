# claude-mem-cloud

## 一句话

一个围绕 Claude 记忆系统做的云端化扩展，重点处理跨会话记忆的持久化、检索和 Provider 适配。

## 解决的问题

AI 工具一旦开始承担连续工作，真正浪费成本的往往不是单轮上下文不够，而是每次开新会话都要把同样的约束、偏好、历史判断再解释一遍。人记得项目在往哪走，系统却总要重新认识你一次。

短期看这只是重复输入，长期看就是质量波动和注意力损耗。很多本来应该积累下来的经验，最后都变成了反复重建的上下文。

## 为什么选这个方案方向

一个常见思路是继续扩上下文窗口，或者把历史粗暴塞回模型里。但上下文越长，成本越高，噪音也越重，而且“记住更多”并不等于“在正确的时候拿回来”。

所以我没有继续沿着堆 token 的方向走，而是转向持久化记忆、分层检索和可替换的 Provider 边界。核心不是让系统永远记住所有东西，而是让它在需要的时候，以合适成本找回真正有用的那部分经验。

## 我关注的效果 / 质量标准

我最关注的是记忆能不能跨会话稳定存在，检索结果是不是足够贴近实际需要，以及迁移到不同运行环境时，这套能力是否还能保持一致。

我并不追求“记得越多越好”。更重要的是噪音不要失控，取回成本不要失控，记忆本身不要变成新的负担。

## 我想展示的工程判断

这个项目体现的是我对 AI 记忆系统的一个判断：真正有价值的能力不是无限存储，而是把经验压缩成可检索、可复用、可迁移的结构。

记忆如果不能在正确的时候被找回来，就只是另一种形式的堆积。
